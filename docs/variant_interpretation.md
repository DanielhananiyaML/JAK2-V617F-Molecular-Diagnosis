# JAK2 V617F Variant Interpretation

## Scope

This document provides a research and educational framework for interpreting the canonical JAK2 V617F variant. It is not a clinical reporting protocol.

## Variant identity

- Gene: **JAK2**
- Transcript: **NM_004972.4**
- cDNA: **c.1849G>T**
- Protein: **p.Val617Phe**
- dbSNP: **rs77375493**
- Reference assembly used for the project: **GRCh38**
- Genomic representation: **chr9:5073770 G>T**
- Variant class: **missense SNV**
- Domain: **JH2 pseudokinase domain**

## Interpretation layers

### 1. Sequence identity

Confirm the genome assembly, transcript accession/version, genomic allele, HGVS expression, and dbSNP identifier before downstream interpretation.

### 2. Molecular consequence

The G>T substitution changes the encoded amino acid from valine to phenylalanine at codon 617, producing **p.Val617Phe (V617F)**.

### 3. Biological consequence

JAK2 V617F is a gain-of-function driver alteration that promotes abnormal JAK-STAT signaling and myeloid proliferation.

### 4. Disease context

The alteration is strongly associated with classical Philadelphia chromosome-negative myeloproliferative neoplasms, particularly polycythemia vera, and is also found in essential thrombocythemia and primary myelofibrosis.

### 5. Clinical context

A molecular result should be interpreted alongside complete blood count findings, peripheral blood and/or bone marrow morphology, clinical findings, and additional molecular testing where appropriate.

## Important reporting principle

A negative JAK2 V617F result does not by itself exclude an MPN. Depending on the clinical and morphologic context, other driver alterations such as **CALR** and **MPL** may require investigation.

## Somatic versus germline interpretation

JAK2 V617F is principally relevant as an acquired/somatic driver alteration in MPNs. Database records can contain submissions using different interpretation frameworks; therefore, database classifications should be read in their specific clinical context rather than copied into a report without review.

## Evidence sources

The project should document the database version/access date and preserve the exact evidence used for each interpretation. Core resources include ClinVar, dbSNP, NCBI Gene, Ensembl, UniProt, COSMIC, and peer-reviewed literature.
